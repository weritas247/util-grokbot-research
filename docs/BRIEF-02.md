# Codex 작업 지시 #2 — 리뷰 1차 수정사항

감독자 리뷰 결과(1280/390 스크린샷 기준). 아래를 모두 고쳐. ARCHITECTURE.md는 계속 기준 문서.
로컬 테스트 서버 포트는 **18791** (8765는 다른 프로젝트가 사용 중). scripts/screenshot.py 기본 URL을 http://127.0.0.1:18791 로 바꾸고 `--url` 인자로 바꿀 수 있게 해.

## 코드 품질
1. index.html, assets/app.js, assets/styles.css가 한 줄로 압축돼 있음 → 사람이 읽고 고칠 수 있게 정상 포맷(들여쓰기, 줄바꿈)으로 다시 작성. app.js는 역할별 모듈로 분리(예: assets/js/data.js 로더, render/*.js 섹션별 렌더러, search.js, filters.js, theme.js, main.js). CSS는 디자인 토큰(:root 변수) → 레이아웃 → 컴포넌트 순서로 주석 구분.

## 데이터 (원문 사실만 사용, 새 사실 금지)
2. summary.json 제목이 "핵심 요약 1~7"로 무의미함 → 원문 문장의 핵심을 그대로 줄인 짧은 제목으로(예: "10월 말 대형 업데이트 몰림", "요금제가 X Subscription으로 통합", "공식 사례: 봇 하나에 일 하나 + 사람 승인", "1인 게임 스튜디오: 봇 14개 + 코딩 에이전트", "커뮤니티 공통 팁", "공유 컴퓨터·사용량 주의", "한국 사이트 IP 차단 우회"). summary는 원문 그대로.
3. updates.json: title과 summary가 똑같음 → title은 짧은 헤드라인(원문 앞부분/핵심 기능명, 예: "v0.78.1 — 쇼핑·구독 템플릿", "Vault 발표 + v0.75.5"), summary는 원문 전체 문장 유지. 원문 단어를 쓰고 없는 내용 추가 금지.
4. 모든 파일 tags가 "요약/업데이트/팁/주의/추천" 같은 섹션 이름뿐 → 내용 주제 태그로 교체(BRIEF-01의 태그 어휘 사용: Pages, 영상, Vault, 보안, 루틴, 요금제, 사용량, GitHub, 커넥터, 모바일, 음성, 이메일, 쇼핑, 승인, 공유 컴퓨터, 스킬, 웹훅, 한국 사이트 등). 항목당 1~3개. 섹션 이름과 같은 태그 금지.
5. meta.json에 `"baseline_added_at": "2026-10-29"` 추가. NEW 배지는 added_at이 baseline보다 **이후**이면서 last_updated 기준 7일 이내일 때만 표시(지금은 전 항목에 NEW가 붙어 소음). README와 ARCHITECTURE의 NEW 규칙 설명도 이렇게 갱신(docs/ARCHITECTURE.md의 해당 한 줄만 수정 허용).

## 화면
6. 홈에 **"최근 소식"** 블록이 없음 → 히어로 아래에 최신 updates 5개를 컴팩트 리스트(날짜 · 종류 배지 · 헤드라인, 클릭 시 타임라인 항목으로 이동)로 추가. "타임라인 전체 보기 →" 링크.
7. 히어로 통계 카드: 맞춤 추천 개수도 포함(6개), 카드 클릭 시 해당 섹션으로 이동. 모바일에선 3열 컴팩트(숫자+라벨)로 높이 줄이기.
8. 섹션 머리말 "GROK BOT RESEARCH" 반복 제거 → "01 · UPDATES" 처럼 섹션 번호 + 짧은 영문 라벨, 그리고 섹션 제목 옆에 항목 개수(필터 적용 시 "8개 중 3개").
9. 타임라인: (a) 날짜 표시를 "2026.10.27"(date_label이 있으면 그 원문 표기를 작은 회색 보조 텍스트로)로 통일, KST 시각은 한 번만 표시(지금 중복). (b) 카드 패딩 줄여 컴팩트하게, 헤드라인은 18px 굵게, 요약 16px. (c) 기본은 최신 8개만 보이고 "이전 업데이트 12개 더 보기" 버튼(필터/검색 시엔 전부). (d) 월 필터를 네이티브 select 대신 칩 그룹(전체/10월/9월/8월 — 데이터에서 자동 생성)으로, 종류 필터 칩과 같은 스타일. 선택된 칩은 강조색 채움, 미선택은 테두리.
10. 사용 사례 카드: 상단에 actor(예 "1인 게임 스튜디오")를 작은 강조 라벨로, 제목, 요약, metrics는 굵은 하이라이트 칩, 카테고리 필터는 category 기준(+태그 보조). 카드 높이 정렬.
11. 주의할 점: severity 라벨 "높음/보통/참고"를 아이콘(SVG)+텍스트 배지로, 섹션 상단에 각 개수 요약. "출처 수준" 안내 박스 본문 앞의 중복된 "출처 수준:" 문구 제거.
12. 맞춤 추천: 번호 단계형(세로 스텝) 레이아웃 + Arda 인용구를 큰 인용 블록으로. context(caption)는 상단 안내 박스.
13. 출처: type별 그룹 제목(공식 변경 기록/공식 뉴스/공식 문서/공식 X/커뮤니티/블로그/리뷰), 카드에 사이트 도메인·날짜·"이 출처를 쓰는 항목 N개"(다른 json에서 url 매칭으로 자동 계산).
14. 내비게이션: 모바일(≤720px)에서 브랜드 "그록봇 리서치"가 사라짐 → 1행: 브랜드 + 검색·테마 버튼, 2행: 가로 스크롤 섹션 칩(스크롤바 숨김, 현재 섹션 칩 강조·자동 스크롤). 아이콘(⌕, ◐) 글리프 대신 인라인 SVG(돋보기, 해/달).
15. 해시 딥링크 버그: http://127.0.0.1:18791/#sources 로 열면 해당 위치로 안 가고 헤더가 아래로 밀려 보임 → 렌더 완료 후 location.hash 대상으로 스크롤, section에 scroll-margin-top(헤더 높이) 적용, sticky 헤더는 top:0 고정.
16. 검색: 결과 항목에 섹션 배지 + 제목 + 요약 앞부분(매치 단어 <mark> 하이라이트), 결과 개수, 키보드 ↑↓/Enter 이동, 결과 없을 때 안내. 검색 대상에 sources 포함.
17. 전반 타이포: 본문 색 대비 높이기(라이트 본문 #1f2330 근처, 보조 #5b6170), 카드 안 출처 링크는 "출처" 라벨 + 외부 링크 아이콘, 태그 칩과 출처 줄 간격 정리. 다크 모드 강조색 대비 AA 확인.
18. 푸터: 데이터 갱신일, 항목 수, "새 조사 추가 방법은 README 참고", 원본 리서치 Page 링크.
